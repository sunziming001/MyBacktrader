# 规格 0001：一期 · A 股回测与选股工具

> **发布状态**：已发布为 GitHub Issue [#1](https://github.com/sunziming001/MyBacktrader/issues/1)，label `ready-for-agent`。本文件为存档副本。

---

## Problem Statement

我需要一套自己完全掌控的 A 股策略回测与选股工具，但现有方案都不合适：

- **现成的量化平台**把数据、引擎、策略都封装好了，我无法确认它的撮合是否遵守 T+1、涨跌停与停牌规则，也无法确认它是否在处理复权时引入了前视偏差。**结论不可信的回测比没有回测更危险**，因为它制造虚假信心。
- **通用的向量化回测库**（如 `vectorbt`）无法表达 A 股制度约束——T+1、涨跌停不可成交、停牌跳过都是**路径依赖的顺序约束**，向量化引擎天生难表达。
- 我手上已有**完整的本地数据资产**（通达信 `vipdoc`，11 年日线 + 权息事件 + 2.5 GB 财务数据），但它们是未公开格式的二进制文件，没有可信的解析工具。

同时，我需要的产出有两种：**验证策略是否有效**（回测），以及**每天得到一份可执行的候选集**（选股）。这两者在语义上不同，但应当共享同一套数据与信号定义，否则同一条件写两遍必然漂移。

## Solution

一个库优先（`mbt`）的 Python 工具，在我自己的机器上解析本地通达信数据、执行严格遵守 A 股制度的组合回测，并基于同一套信号层做截面选股。

- **数据层**自研解析三种通达信二进制格式，落盘为「原始价 + 复权因子」，按需计算后复权（回测）与前复权（展示）视图。
- **信号层**是本项目的中枢：指标、过滤信号、排序因子一律算成 `date × symbol` 的**标的宽表**，回测按列取时序、选股按行取截面——**同一个函数，两个消费方向**。
- **回测层**用 `backtrader`（精确 pin、隔离在自有协议后），从第一天实现 T+1、涨跌停、停牌、费用与印花税，并按「生效日期 × 板块」查表以适配 11 年间的规则变更。
- **选股层**把过滤器 + 排序 + 取前 N 组装成选股规则，既能独立产出候选集，也能作为回测的入场过滤器。
- **交互**以 Python 库为内核（可被脚本、notebook、测试直接调用），外套一层薄 CLI 供日常跑批。
- **时点正确性**贯穿全项目：任何计算只用评估日已可知的信息，复权事件按日期过滤、财务数据按公告日对齐。

一期的第一颗曳光弹是**单标的、端到端最窄切片**：从本地 `.day` 文件解析 → 回测 → 输出净值曲线与交易明细。主管道贯通后再横向加宽至组合、内置信号库、选股规则，最后接上基本面过滤。

## User Stories

### 数据解析与存储

1. 作为策略研究者，我想解析本地 `vipdoc` 下的 `.day` 日线文件，这样我就能用我已有的数据资产，而不必依赖网络接口。
2. 作为策略研究者，我想让解析器覆盖 `sh` / `sz` / `bj` 三个市场，这样北交所标的也能进入我的股票池。
3. 作为策略研究者，我想让解析结果落盘为列式文件并按标的组织，这样一次解析能被多次回测复用，而不必每次重解析。
4. 作为策略研究者，我想以增量方式更新数据，这样每次收盘后只追加新记录，而不是重新解析全部文件。
5. 作为策略研究者，我想在增量更新时校验边界记录的一致性，这样当通达信回补或修正历史数据时，我能回退并重解析该标的，而不是静默漏掉修正。
6. 作为策略研究者，我想让数据解析由我手动触发，这样我不会在明知有数据修正的情况下仍被定时任务覆盖。
7. 作为策略研究者，我想让数据源路径可配置，这样我能在仓库外放置数据目录，并在换机器时只改一处配置。
8. 作为策略研究者，我想让数据访问层按 adapter 设计，这样将来加入网络数据源（用于补齐退市标的）时不必触动上层。

### 品种判定与股票池

9. 作为策略研究者，我想让数据层按代码前缀判定**品种**（股票 / 指数 / 可转债 / 基金），这样可转债与板块指数不会混进我的选股结果。
10. 作为策略研究者，我想让股票池只从判为「股票」的品种中构建，这样我的截面统计不会被我无意中纳入的非股票标的污染。
11. 作为策略研究者，我想让股票池在**每个调仓日按当日状态动态计算**，而不是用一份固定名单，这样新上市的标的会自然进入、退市前的历史会自然保留。
12. 作为策略研究者，我想让股票池默认排除 ST 与 *ST 标的，这样我不会把风险警示股当成正常标的。
13. 作为策略研究者，我想让股票池默认排除上市不足 60 个交易日的次新股，这样新股上市初期的异常波动不会干扰信号。
14. 作为策略研究者，我想让股票池默认纳入主板、创业板、科创板与北交所，这样我不会因为一个不成立的「数据缺口大」印象而白白损失标的。
15. 作为策略研究者，我想能显式配置上述每一条准入规则，这样当我想研究 ST 股或次新股时不必改代码。

### 复权

16. 作为策略研究者，我想让落盘的是**原始价**与**复权因子**，而不是任何已复权的价格序列，这样我的历史数据不会因为未来的一次分红而整体改变。
17. 作为策略研究者，我想在回测时使用**后复权**视图，这样价格序列不引入未来信息。
18. 作为策略研究者，我想在展示时使用**前复权**视图，这样图表与行情软件的习惯一致。
19. 作为策略研究者，我想让复权只由除权除息类事件驱动，这样股本数量类事件不会被错误地用来调整价格。
20. 作为策略研究者，我想让复权因子按评估日过滤事件后计算，这样尚公告、未除权的未来事件不会把未来信息注入历史。
21. 作为策略研究者，我想能独立验证复权因子，这样我不必依赖一个自研解密算法的自证正确。

### 时点正确性

22. 作为策略研究者，我想让所有计算都按**评估日的已知信息**进行，这样我的回测结论不会因为前视偏差而虚高。
23. 作为策略研究者，我想让财务数据按**公告日**对齐，而不是按报告期，这样我不会提前数月知道尚未公布的财报。

25. 作为策略研究者，我想让股票池、过滤信号、排序因子都不得引用评估日之后的记录，这样三类计算在时点上保持一致。

26. 作为策略研究者，我想让**指标**（均线、ATR、成交量比等）由单一标的的价量序列算出、不含判断，这样我能自由组合它们。
27. 作为策略研究者，我想让**过滤信号**是对单一标的是否合格的判断，这样我能用它构建股票池与选股规则。

## Implementation Decisions

### 包结构与模块边界

采用**按技术分层**的包结构，让「信号层被回测与选股共享」这一架构主张在文件树上一眼可见：

- **数据层**：通达信格式解析（日线 / 权息事件 / 财务数据）、品种判定、数据源 adapter、列式存储与增量更新。
- **信号层**：指标、过滤信号、排序因子，一律**标的宽表**进出；含内置信号库。
- **回测层**：引擎协议 + `backtrader` 适配、撮合与制度约束、费用模型、指标计算、产物落盘。
- **选股层**：选股规则的组装与执行。
- **CLI 层**：`backtrader` 之上的薄包装。

不采用「按回测与选股分」的结构——那会让共享的信号层要么被复制两份、要么被塞进一个不合理的位置，等于在目录结构上背叛 ADR-0001。

采用 `src/` 布局，使测试跑的是安装后的包，避免导入路径类的假通过。

### 关键接口契约

**信号函数**是项目的中枢契约，形状统一为：

```
DataFrame[date × symbol]  →  DataFrame[date × symbol]
```

- 指标返回浮点数，过滤信号返回布尔值，排序因子返回可横向比较大小的浮点数。
- 回测按列取时序，选股按行取截面——**同一个函数，两个消费方向**。
- 纯函数：无 I/O、无状态、不读全局配置。

**回测入口**是一个运行定义对象（含策略、参数、区间、股票池规则、基准），CLI 参数是它的薄映射。一期不做配置文件形式，`run` 元数据作为**产物**落盘（与作为**输入**的配置文件区分开）。

**数据源 adapter** 接口接受一个根路径，本地通达信是其一期唯一实现。

### 制度规则按日期与板块查表

涨跌幅限制与费率**不得写成常量**。以「生效日期区间 × 板块」的规则表建模，撮合逻辑按**成交日**取当日生效的规则。需覆盖的已确认变更：

- 涨跌幅：主板 10%；ST 5%；创业板自 2020-08-24 起由 10% 改为 20%；科创板 20%；北交所 30%。
- 印花税：2023-08-28 起由卖出 0.1% 减半为 0.05%。
- 过户费：2022-04-29 起沪深统一为双向收取。

规则表以**可配置数据文件**形式存在，而非硬编码。

### 复权

落盘原始价与复权因子；回测计算后复权视图，展示计算前复权视图。

- 复权仅由除权除息类事件驱动。股本数量类事件**不参与**价格调整（它们另有用途：估值类因子需要每个评估日的总股本）。ETF 份额折算类事件不参与，因为范围不含 ETF。
- 复权事件按 `date ≤ 评估日` 过滤后才可使用。
- 复权因子必须**独立于价格解析**被测试。

### 通达信格式解析

三种格式一律自研，第三方库仅作测试对照或字段映射来源：

- **日线**：定长记录，是三种格式中最简单的一种。
- **权息事件**：含加密，自研理由是**法律**——参照实现的仓库无任何许可证文件，拷贝其代码存在明确瑕疵；而这是数据提供方的文件格式，不是该库的智慧财产。
- **财务数据**：明文定长，自研理由是成本——本项目只需约 3–5 个字段。若将来铺开 50 个以上基本面因子，应重新评估改用 MIT 许可的现成库。

### 数据质量

缺口跳过、异常报错、**永不填充**。异常检测需能区分正常涨跌停与数据错误。区分停牌与退市是这套规则的实现要求。

### 引擎选型与隔离

`backtrader` 精确 pin（不用兼容范围），并隔离在回测层自有协议之后；数据层与信号层**不得**依赖它，只使用 pandas。同版本的 `collections.Iterable` 缺陷（Python 3.10 移除该别名）以包内兼容 shim 修补，**并配一个真正触发该 API 的测试**，使 shim 不会静默失效。

## Testing Decisions

### 什么算好测试

只测**外部行为**，不测实现细节。信号层是纯函数，所以测试天然是「给定标的宽表，断言标的宽表」。回测层的测试断言**资金与持仓的精确数值**，而非断言内部调用了哪些方法。

### 测试缝

**S1 — 库公开 API（最高缝）**：回测与选股的端到端测试全部走库入口，不走 CLI。黄金用例钉在这里：喂入手工构造的极小数据，断言最终资金精确相等。

**S2 — 通达信数据源根路径（解析层缝）**：解析函数接受数据源根路径，测试指向仓库内 fixture 目录（含除权、含停牌、含一字板的极小真实二进制样本）。这使得测试自足——换机器后不会因为找不到本地通达信目录而失败。

**信号函数契约**不需要缝：纯函数本身即可测。

**刻意不设的缝**：回测层会定义引擎协议（架构缝），但**测试绝不使用假引擎**。黄金用例必须跑真实的 `backtrader`，因为要验证的正是「真实引擎 + 我们写的撮合与制度规则表」这个组合；换成假引擎，测的就只剩我们自己的记账逻辑，而漏掉最可能出现意外的地方——引擎的实际撮合行为。

### 要测的模块

- **解析层**：三种格式的字节布局解析（对 fixture 样本）、品种判定、增量更新的边界校验。
- **复权**：复权因子的数值正确性，并与独立 oracle 对账（开发期的第三方读取实现，仅作对照，不作依赖）。
- **制度规则表**：按成交日取当日生效规则的查表逻辑，含跨变更日期的边界。
- **撮合**：T+1、涨跌停不可成交、停牌跳过、费用与印花税，用手工构造的极小数据逐条锁死。
- **信号层**：每个内置信号的数值正确性（含边界：全 NaN 窗口、恰好 N 日新高）。
- **回测层**：黄金用例（能手算的微型回测，断言最终资金精确相等）；真实数据的「买入持有」与手工计算对账，作为引擎首版完成后的一次性验尸。
- **时点正确性**：断言未来日期的事件与公告日之后的财报不会被纳入评估日的计算。

### 测试数据

fixture 提交在仓库内，且**不宜提交整段 11 年数据**——只提交覆盖关键场景的裁片（含除权、含停牌、含一字板的最小样本）。真实数据的冒烟测试以标记隔离，缺席即跳过而非失败。

## Out of Scope

- **分钟线与日内数据**：本地通达信安装中分钟线目录为空，且数据源不会提供。
- **网络数据源**（akshare / tushare / baostock）：一期只吃本地数据；接入第二数据源会引入两套复权口径与字段定义的一致性负担。
- **参数寻优**（网格搜索、贝叶斯、遗传）：寻优会放大引擎的任何错误，在引擎正确性被证明之前不做。一期只支持同一策略换一组参数批量跑并对比结果。
- **Web UI / 桌面 GUI**：收益只是把敲一行命令变成点一下，而先吃掉大量时间。
- **配置文件的 run 定义**：一期用 CLI 参数，配置文件是自然的第二步。
- **自研表达式语言 / 通达信公式风条件**：好用是因为原厂实现了解释器，自造等于重写半个项目。
- **TA-Lib**：未安装，且内置信号库足以覆盖常用条件。
- **`gp{sh,sz,bj}NNNNNN.dat` 的逆向**（占财务数据 62%）：tag 语义未确认且全网无解析器，产出不确定，不进关键路径。一期改用权息事件中的股本数据自算市值与估值；两者日后可互相校验。
- **新股上市首日 / 前 5 日的特殊涨跌幅**：股票池已排除上市不足 60 个交易日的次新股，恰好把该场景挡在门外。
- **制度「精细」档**：集合竞价、最小变动价位、按成交量比例部分成交。
- **ETF 与基金策略**（含份额折算类事件）。
- **CI**：单人项目、无外部贡献者，且 CI 跑不了机器本地的真实数据。测试本地跑。
- **pre-commit 钩子**：待第一份代码写完后配置，避免先摆一个空钩子养成跳过的习惯。
- **`vectorbt` 等向量化引擎**：范式与 A 股制度约束错配，且要求 Python ≥3.11。

## Further Notes

### 已确认的已知局限

**幸存者偏差无法用本地数据消除**。实测确认：退市代码在价格数据与财务数据中**双双缺失**——1995 / 2005 / 2010 年财务文件中 100% 的代码在 2025 年仍存在，而多个已知退市代码在所有 147 期中均不出现。因此任何回测结论**不得声称已排除幸存者偏差**。消除它的唯一途径是将来接入网络数据源。

**数据窗口等于本地已下载的历史**（当前 2015-01 → 2026-09，约 2800 个交易日）。它可通过通达信客户端下载扩展，因此不设上限、不作为局限记录。

### 数据资产盘点

机器上已存在、尚未使用的资产，作为路线图上的已知项：

- `vipdoc/cw` 的按期财务数据共 147 期（1988→2026-09），含真实公告日字段。
- `gp{sh,sz,bj}NNNNNN.dat`（1.5 GB）疑似每日个股指标（市盈率、换手率、市值等），待日后逆向并与自算市值对账。

### 落地顺序

1. **曳光弹**：单标的端到端最窄切片（解析 → 回测 → 净值曲线与交易明细），验收标准具体到不可能含糊。
2. **横向加宽**：组合回测与仓位管理 → 内置信号库 → 选股规则 → 基本面过滤。
3. **贯穿始终**：制度约束、费用、复权与时点正确性从第一天就在管道里，不做为后续阶段。

### 术语

本规格全程使用 `CONTEXT.md` 的词汇（标的、品种、股票池、调仓日、停牌、退市、原始价、复权因子、后复权、前复权、复权事件、评估日、公告日、报告期、累计值、单季值、前视偏差、指标、过滤信号、排序因子、选股规则、策略、回测、净值曲线、回撤、基准、持仓）。规格与实现若与任一 ADR 冲突，须显式提出而非静默覆盖。
