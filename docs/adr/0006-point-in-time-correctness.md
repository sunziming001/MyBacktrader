# 一切计算按「评估日已知信息」进行，防止前视偏差

任何复权因子、过滤信号、排序因子与股票池，一律按**截止到评估日 `d` 的已知信息**计算。凡携带日期的数据，按 `date ≤ d` 过滤后才可使用。

## Context

实测发现通达信 `gbbq` 的事件日期范围延伸到 **评估日之后**（例：2026-09-11 读到的事件日期上界为 2026-09-18）。这是「已公告、未除权」的预告事件。

若把整张事件表不加过滤地套用到历史序列上，就会**把未来的除权信息注入过去**——这是最隐蔽的一类前视偏差：它不会报错、不会让净值曲线出现异常，只会让策略显得**特别准**。

同样的风险以另一种形式出现在基本面数据上：财务报表有报告期与**实际公告日**之别，用报告期对齐等于提前知道了尚未公布的数字。

## 决策

确立一条贯穿全项目的规则：**计算必须可回溯到评估日当时已知的信息**。

- 复权事件：按 `date ≤ d` 过滤。
- 基本面数据：按**公告日**对齐。**实测确认本地财务数据含真实公告日字段**（`gpcw` 数据块内 float 索引 313 / 字节偏移 1252，以 `YYMMDD` 整数存于 float32），已与真实披露日期核对：平安银行 2023 年报为 2024-03-15、贵州茅台为 2024-04-03、浦发银行 2024-04-30；季度滞后中位数：一季报 27 天、半年报 59 天、三季报 29 天、年报 114 天——**均晚于报告期，属真实公告日**。
- 信号与股票池：不得引用任何 `d` 之后的记录。

**无需**退化为「用法定披露截止日近似」——那是公告日缺失时的备选，实测不必要。唯一边界情况是约 2005 年以前该字段退化为占位值（等于报告期），而本项目价格数据自 2015 年起，故与实现无关。

另需注意：同一数据块内**累计值与单季值混存**（累计：营业收入 float 73、净利润 float 94/95；单季：营业收入 float 229、归母净利 float 231、float 310/311；资产负债表字段为时点值）。取用时必须明确所选字段是累计还是单季，**混用会导致同比/环比计算错误**。

## Consequences

这条规则**在代码里看不出来**，且违反它的结果不是失败而是「更漂亮的结果」，因此必须成文。它同时是本项目可复现性纪律（见 ADR-0003）的另一面。

实现上意味着复权因子与基本面字段都**不能预计算成全历史常量**，必须接受一个评估日参数；这正是 ADR-0003 选择「存原始价 + 因子、用时计算」的同一个理由。
