# 一切计算按「评估日已知信息」进行，防止前视偏差

任何复权因子、过滤信号、排序因子与股票池，一律按**截止到评估日 `d` 的已知信息**计算。凡携带日期的数据，按 `date ≤ d` 过滤后才可使用。

## Context

实测发现通达信 `gbbq` 的事件日期范围延伸到 **评估日之后**（例：2026-09-11 读到的事件日期上界为 2026-09-18）。这是「已公告、未除权」的预告事件。

若把整张事件表不加过滤地套用到历史序列上，就会**把未来的除权信息注入过去**——这是最隐蔽的一类前视偏差：它不会报错、不会让净值曲线出现异常，只会让策略显得**特别准**。

同样的风险以另一种形式出现在基本面数据上：财务报表有报告期与**实际公告日**之别，用报告期对齐等于提前知道了尚未公布的数字。

## 决策

确立一条贯穿全项目的规则：**计算必须可回溯到评估日当时已知的信息**。

- 复权事件：按 `date ≤ d` 过滤。
- 基本面数据：按**公告日**对齐。**实测确认本地财务数据含真实公告日字段**（`gpcw` 数据块内 float 索引 313 / 字节偏移 1252，以 `YYMMDD` 整数存于 float32），已与真实披露日期核对：平安银行 2023 年报为 2024-03-15、贵州茅台为 2024-04-03、浦发银行 2024-04-30；季度滞后中位数：一季报 27 天、半年报 59 天、三季报 29 天、年报 114 天——**均晚于报告期，属真实公告日**。
- 信号与股票池：不得引用任何 `d` 之后的记录。

**无需**退化为「用法定披露截止日近似」——那是公告日缺失时的备选，实测不必要。唯一边界情况是约 2005 年以前该字段退化为占位值（等于报告期），而本项目价格数据自 2015 年起，故与实现无关。

另需注意：同一数据块内**累计值与单季值混存**（累计：营业收入 float 73、净利润 float 94/95；单季：营业收入 float 229、归母净利 float 231、float 310/311；资产负债表字段为时点值）。取用时必须明确所选字段是累计还是单季，**混用会导致同比/环比计算错误**。

## Consequences

这条规则**在代码里看不出来**，且违反它的结果不是失败而是「更漂亮的结果」，因此必须成文。它同时是本项目可复现性纪律（见 ADR-0003）的另一面。

实现上意味着复权因子与基本面字段都**不能预计算成全历史常量**，必须接受一个评估日参数；这正是 ADR-0003 选择「存原始价 + 因子、用时计算」的同一个理由。

## 修订：有一族数据**天然无法**满足本规则，已登记为不可回溯缺口（票据 #50）

上面说「基本面字段必须接受一个评估日参数」——前提是历史还在。`vipdoc/cw` 的 `gpXX*.dat`
（`mbt.data.gp`）不满足这个前提，故必须单独登记，否则接手的人会以为「按评估日过滤一下」就能用。

**事实**：这族文件里的日频 id 只保留**最近 2000 条**，是一个滚动窗口。证据不是「条数恰好
2000」（那可能是巧合），而是**同一文件里多个 id 共用同一段起止日期**：实测
`gpsh880411.dat` / `gpsh881111.dat` / `gpsh881416.dat` 各有 14 个 id 全部正好 2000 条，
且这 14 个 id 的日期跨度分毫不差（20180622~20260915）；全量 8,976 个文件里 5,142 个（57.3%）
含至少一个这样的 id。

**结论**：对这些 id 而言，「评估日当时的值」**已经不在文件里**——旧记录是被覆盖掉的，不是
没下载。故它们**无法**做到时点正确，也没有「从别处补回来」的路（目前没有）。

**因此**：任何用到这些 id 的过滤信号、排序因子或股票池，**不得声称时点正确**；这属于本 ADR
要求「明确记录、不假装是历史快照」的那一类缺口。读 `mbt.data.gp` 拿到的**永远是「现在这一版」**。

与 `gpcw` 的区别值得写清：那边老报告期还在，只是公告日可能退化为占位值（可用年份门挡住）；
这边是**整段历史被删**，没有任何判据能识别出一条记录是「当时值」还是「覆写后的值」。

## 修订二：`GPONEDAT` 的一致预期字段是**快照**，历史同样不可得（票据 #50）

前瞻分支要用的那四个字段（``GPONEDAT(4)`` 财年T、``(5)`` EPS_T、``(8)`` 净利T、``(23)``
PE预期）来自 ``T0002/hq_cache/gpSHone.dat`` / ``gpSZone.dat``（见 :mod:`mbt.data.gpone`，
ADR-0008 修订二）。这一族**更彻底**：它不是滚动窗口，而是**只有一条**。

每个 ``(代码, 字段)`` 在文件里**只出现一次**，即「最新值」；文件里**没有日期字段**。故
机构上一回给出的预测已被这一回**覆盖**——不是「旧记录被挤掉了」，是**根本没有旧记录**。

**因此**：一致预期类字段（4..25、35..41、44..47）**不得**用于任何声称时点正确的回测。
可用于**非回溯**场景（今天的池子、今天的读数）。文件 mtime 是客户端重写文件的时刻，不是
这些数值各自的发布日，**不能**当数据日期用。

这也解释了为什么「用前瞻」这条规则在本项目里做不到时点正确：它天生读的是「最新的一致预期」，
而最新的一致预期恰恰是评估日**之后**才形成的东西。若将来要把它用于回测，缺的不是解析器，
是一份**带发布日的一致预期历史**——本地没有，只能外部采购或从别处重建。

## 修订三：一致预期**可以**用在一个地方——盘后选股，闸门是数据写入日（票据 #50 修订）

修订二说这族数据「可用于非回溯场景（今天的池子、今天的读数）」。那句话当时**没有可执行的
判据**，于是「哪天算今天」只能靠人记住。现在它有一个判据，且落在数据自己身上：

    评估日 ≥ 该标的所在文件的最后写入日   ⇒  前瞻可用；否则退回历史口径。

理由：文件 mtime 是客户端**写下**这份快照的时刻，也就是「我们最早可能看到它」的时刻。评估日
在它之前时，手上这份内容**可能已被后来的下载覆盖过**——不可知，故不许用。

这条比「必须是今天」**更准**：若一周没下载，那一周内的评估日都可用（那时文件内容确实没变过）；
而任何回溯到写入日之前的评估日会自动退回历史口径。**回测因此永远用不上前瞻**——它的评估日
全在写入日之前，不需要额外判断。

写入日按**文件**算，故沪深两市各自生效：实测 ``gpshone.dat`` 写于 2026-08-26 而
``gpszone.dat`` 写于 2026-09-17，于是评估日 2026-09-16 上只有沪市走前瞻（184/356）。
日常任务（收盘后下载、随即选股，评估日 = 写入日）不会碰上这个分叉。

### 「没有前瞻」有两种，报的也是两种话

逐标的降级时分两支走，**不能合成一个数**：

- **市场压根没有这族文件**——本机是北交所（客户端没落 ``gpbjone.dat``，公式文档说
  ``GPONEDAT`` 适用沪深京）。这是**已知覆盖缺口**，安静退回历史即可，不该报警。
- **市场有文件、但文件读不到**——几乎总是 ``--forward-root`` **指错了目录**。这个必须喊。

实测全池 5,375 个标的里北交所占 276 只，**每一只都会落进第一支**。合成一个数的话，日更任务
每天都会印一次「276 个标的的一致预期文件读不到——指对了吗？」，而真正指错目录的那天就淹在
这句每天出现的话里。故产物里分成 ``unsupported`` 与 ``unreadable`` 两个计数，前者只陈述
事实、后者才带问句；判据落在 :meth:`mbt.data.gpone.GponeDataSource.covers`（只问市场，
不看文件在不在）。

### 落点：只有 ``mbt screen`` 有这一步

``--forward-root`` **只加在 ``screen`` 子命令上**，回测侧没有这个开关；替换也只发生在
``run_screen_command`` 里。于是回测在**结构上**够不着一致预期——不是靠运行时判断挡住的，
而是根本没有那条代码路径。两条测试分别钉住这两半（参数表、以及「就算把调用点挪到共用路径，
回测那套 args 也点不亮它」）。规则侧一个参数都没加：``b1_screen`` 照旧读面板的 PE 与百分位，
变的只是喂进去的数据。

### 已知代价：百分位是**混口径**的

``选用PE`` 只有评估日那一行换成前瞻值（历史各行没有前瞻可换），而「PE 百分位低」那道门读的
百分位是从 ``选用PE`` **重算**的，故它的窗口里混着两种口径：历史的点是历史 PE、评估日那点是
前瞻 PE。实测（356 个标的，评估日 2026-09-16）：

- ``PE 为正``：248 → 265，新进 17、**零出**。方向符合预期——历史口径下按已披露财报在亏、
  按一致预期不亏的标的，现在进得来了。
- ``PE 百分位低``：116 → 120，看着几乎没动，底下却换掉了 **38** 个标的（21 进 17 出）；
  另有 7 个标的的百分位被顶到 **1.0**、12 个掉到 **0.0**，单点最大跳变 **±0.98**。
- 两道门合成：79 → 94。

跳变的机理是窗口跨过零点或前瞻值落在窗口之外：一个「按已披露财报在亏、按预测转盈」的标的，
其前瞻 PE 为正而窗口里的历史 PE 为负，min-max 归一化于是把它判成「处在自己四年区间的最高位」。
那个数**没有含义**。

**这是明码标价认下的，不是笔误。** 要拿掉它，就得改成逐**字段**降级——``PE`` 用前瞻、
``PE 百分位`` 整列退回历史（百分位这个字段本来就没有前瞻版本）。取舍已做过，选了字面忠于
「评估日就用前瞻」的那一版。

### 全池实测：写入日这道闸门确实在做事

同一台机器、全池 5,375 个标的、评估日 2026-09-16（沪深两市各自的写入日不同，见上）：

======================  ======  ================================================
走成了前瞻              1,266   全是沪市标的
市场无此数据              276   北交所，安静退回
写入手比评估日晚        2,830   **全部**深市标的——``gpszone.dat`` 写于 09-17
其余（无该票的预期）    1,003   沪市里没有一致预期、或财年对不上的
======================  ======  ================================================

四类相加正好 5,375，且深市**一只都没走成**——这不是巧合，是写入日那道闸门的直接后果：深市
那份文件写于评估日之后，故深市整市退回历史口径。

这个数**只该当量级看**，因为两件事会一起动：写入日跟着你最后一次下载走，而评估日跟着行情
末根走。隔天再下载、隔天再选股（评估日 = 写入日），深市那 2,830 只里就会有一批转为前瞻。
反过来是**单向**的：重新下载只会把写入日往前推，故它**不会**让任何**过去**的评估日变成可用
——那正是这条判据要的性质。

## 修订四：`选用增` 接进 PEG，于是选股与回测的**候选总体**不再相同（票据 #50 修订）

``选用增`` 在整条公式里只有一个消费者，就是 PEG::

    PEG := IF(选用PE>0 AND ABS(选用增)>0.1 AND 财年T>0, 选用PE/选用增, DRAWNULL)

而 PEG 是 ``undervalued_growth`` 的 ``growth_worth_paying`` 门在读。故「实现选用增」这件事
等于「把 PEG 也换成盘后口径」，落点与修订三同一处：``mbt screen`` 的前瞻那一档。

### 第三道守卫是**新的**，而且它比换口径更狠

``valuation`` 里那份 PEG 只守两道门（``PE>0``、``|增|>0.1``），第三道 ``财年T>0`` 当时是
**刻意不实现**的——``财年T`` 只能从快照读，加进那条按公告日点取的路会注入前视偏差（修订二）。
现在补上它，代价是：「**没有一致预期就没有 PEG**」。实测（池子 4,752 只，评估日所在年 2026）：

=======================  ======  ==========================================
分档                     只数    评估日的 PEG
=======================  ======  ==========================================
无一致预期（财年T≤0）    2,318   缺失——被第三道守卫摘掉
财年对不上当前年份          31   不动，仍是历史 PEG
有预期但预测亏损            83   缺失（``增预期`` 取 0，过不了 ``|增|>0.1``）
有预期但基期亏损/拿不到    194   同上
有预期但``|增预期|≤0.1``     5   同上
所在市场无此数据           140   缺失（``财年T`` 在本机恒为 0）
**PEG 门看得见**         **2,012**  **42.3%**
=======================  ======  ==========================================

即：前瞻那一档下 ``growth_worth_paying`` 只看得到池子的四成二，其余**五成八**被摘掉。

### 这就是明知故犯的那条分叉

回测里 PEG 只在 ``PE≤0`` 或 ``|增|≤0.1`` 处缺失，几乎覆盖全池；盘后选股前瞻档里只剩四成二。
于是**同一个 ``Screen``、两条路的候选总体不同**——不是数值不同，是「谁有资格进这道门」
不同。这与 #73 那条教训（选股用未复权价、回测用后复权）是同一形状的错，区别只在于这次是
**当场认下的**。

认下的理由与修订三一字不差：快照只许非回溯使用，故「回测当时并不知道有没有一致预期」这件事
无法在回测里补偿——回测那一路**结构上读不到** ``财年T``（不是不许读，是没读），于是它只能
按历史口径走。两条路的名单本来就不可互证。

**不含 ``--forward-root`` 时逐格不变**，回测产物因此与本修订之前完全一样——变的是「用了前瞻
的那一次选股」喂进去的那张 PEG 表（与 B1 那次同源：规则侧一行没改）。

### 判据是「知道」还是「不知道」，不是一个「无前瞻就如何」的规则

    PEG 那一格的落点由 ``财年T`` 是**知道**还是**不知道**决定：

- **知道且 > 0**：用 ``选用PE ÷ 选用增``（走前瞻时两者都是预测口径）。
- **知道且 ≤ 0**：缺失。含「文件里这只票没有预期」与「本机没有这个市场的文件」（北交所，
  那儿的 ``财年T`` 恒为 0）。
- **不知道**：一格不动，退回历史那一格。含「评估日早于写入日」（快照不能用在今天，回测走的
  就是这一支）与「文件读不到」（多半是 ``--forward-root`` 指错了目录）。

「不知道」的那两支不抹 PEG 是刻意的：前一支是修订三那条不变式的要求（早于写入日的评估日上
整张表逐格不变）；后一支是不拿一个配置错误去悄悄改候选集——它已经另行报出来了。

``peg_missing`` 报的是评估日那一列**最后**缺了哪些格——从结果数，不从原因数。第一版是「哪条
守卫抹的就在哪个分支顺手记一笔」，于是只数了 ``财年T>0`` 那一道：实测报出 141，真值是 157。
守卫有三条，将来还可能再加，故这个数只能按结果数（见 ``mbt.data.forward._missing_on``）。

### 顺带：成对切换换的是**增长的定义**，不只是数据新旧

``增历史`` 是**当期累计同比**（``FINVALUE(184)``，年初到最近报告期）；``增预期`` 是
「T 年预测净利 ÷ 最近一期年报归母净利 − 1」，是**全年**的。同一只票的增长率可以从 +120% 变成
−5%，于是 PEG 从「有意义」变成「没有意义」，或反过来。故文档与产物里都写「换的是口径」，
不写「换了更新的数据」。

### 开关：白名单，`valuation` 刻意不开

``FORWARD_SCREENS = ("b1", "undervalued_growth")``。``valuation``（旧版规则）也读 PE 与 PEG，
但它留在仓库里的用途恰恰是给新规则当**对照物**——让它跟着换口径，对照也就一起移动了，两份
产物没法比。PEG 的重述再窄一层（``PEG_SCREENS``）：``b1`` 一个 PEG 门都没有，为它按标的各读
一遍基期年报净利是白花的钱。

### 数据快照补上了这两份文件

``run.json`` 的 ``data_snapshot`` 此前只收 ``.day`` 与 ``gbbq``，没收录一致预期那两份——
于是产物说的「这次读了哪些文件」是错的（溯源记录错一处，回头对账就解释不了两份名单为什么
不同）。现在**跑了前瞻才记**，且只记**确实存在**的那几份。

### 本次不做：日更

``b1_daily.bat`` 每天跑的仍然只有 B1。要不要把 ``undervalued_growth`` 也加进去是「部署」的事
（多一条规则就要多定它产物落在哪），与「实现选用增」分开，另开一条 issue。
