# 宽表正名与行情面板

项目里「宽表」一词同时指两种**语义相反、结构上却无法区分**的表，这是本 ADR 要解决的问题：

- **字段宽表**（bar frame）：交易日为索引、**字段**为列（`open` / `high` / `low` / `close` / `volume` / `amount`），一个标的一份。它是数据层的产物，也是引擎的输入。
- **标的宽表**（symbol frame）：交易日为索引、**标的**为列，一格一个数。它是信号层的全部输入与输出（ADR-0001）。

两者形状完全同形，故把前者喂进信号层**不会报错**：实测 `sma(单标的 OHLCV, n=2)` 返回一张列名为 `open/high/low/close/volume` 的「均值表」，即把这 5 个**字段**当成了 5 个**标的**，而结果看上去完全合理。这类静默错答比抛异常危险得多——它会一路流到净值曲线上。

ATR 是第一个撞上这件事的信号：它一行内同时用 `high`、`low`、`close` 三个字段且必须同日对齐，而标的宽表的一格只能放一个数，**`atr(prices, n)` 在标的宽表下写不出输入**。

## 决策

1. **正名**：`字段宽表` 与 `标的宽表` 互斥使用，**裸用「宽表」不再允许**。
2. **引入行情面板**（panel）：字段 → 标的宽表的映射。字段由调用方**显式**声明，**按需组装**——它**不是**行情在全项目中的规范表示；逐标的的字段宽表仍是磁盘与引擎边界的规范形态。
3. **面板消费类信号返回标的宽表**：ATR 的消费方向与 `sma` 相同（列 = 时序、行 = 截面），只是输入多了两张表。故它仍受 ADR-0001 保护，也因而可直接当排序因子。

## Considered Options

- **MultiIndex 列 `(字段, 标的)`**：一处定义、处处清晰，但「行 = 截面」不再无条件成立——每个消费方都得先切成某个字段，ADR-0001 的性质从「天然成立」退化为「切完才成立」。
- **ATR 逐标的在字段宽表上算，截面拼接交给调用方**：信号层得以保持单一形状，但把多字段的复杂度推给每一个调用方，且「同一个函数，两个消费方向」在 ATR 上不再成立。
- **把这件事折进票据 #5**：会让一张已实现的票同时承担「单字段信号库」与「多字段接口」两件事。

## Consequences

- **面板不落盘、不常驻**。全市场全字段面板约 5,602 标的 × 2,800 交易日 × 5 字段 ≈ 6.3 亿格，float64 下约 **630 MB**，且必须**一次性急加载**——这与 `.day` 的逐标的文件布局及增量更新的设计正面冲突。
- **组装器收 `MarketData` 集合**，故**走正门**（`load_market_data`）拿到的行情已是质检的证据，
  面板**不重复**越界检查。这条论证的边界要说清：`MarketData` 的字段是公开的，直接构造它就能
  绕过质检——那与绕过 `load_market_data` 是同一件事，面板不为此负责。
- **组装时强制各字段的 `index` 与 `columns` 完全一致**，但**不要求字段齐全**——只要求「给的字段之间对齐」。跨字段计算的全部正确性建立在同日对齐上，一次性的组装期检查换掉一整类静默错位。
- **字段显式声明**，不推断：`amount` 之类与信号无关的字段没有理由被无声带进计算。
- **不得使用 `backtrader` 自带的 `bt.ind.ATR`**（ADR-0007 的隔离要求）。用它会让 ATR 只在回测中可用、在选股中不可用，而信号层存在的理由正是「同一个函数，两个消费方向」。
