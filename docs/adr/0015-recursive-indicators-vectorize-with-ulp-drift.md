# 递推类指标的向量化：接受末位浮点差，但判据必须零翻转

`ema` 与 `kdj` 的递推从「逐列 pandas」改成「按行 numpy」之后，白线快 **45×**、KDJ 快 **30×**，而数值**不是逐位相同**——最大相对差 4.75e-16（约 1~4 个 ULP）。本 ADR 记录为什么这是**可以接受**的，以及接受它时需要什么证据。

## 背景：逐列做，等于把行数乘上列数

`ema` 与 `kdj` 原先都写成 `DataFrame.apply(_recursive_smooth_series, alpha=...)`——**逐列**跑一次 pandas 流水线（`notna` / `cumsum` / `groupby` / `ewm`）。递推只能沿时间走，这没错；但**列之间互不相干**，所以按列做等于把「行数」的 Python 迭代乘上了「列数」。实测白线（双层 EMA，即两遍）在 467 列 × 7,206 行上要 **3.64s**；全市场 5,451 列就是分钟量级。

改成按行推进（每行一次算完全部标的，numpy 向量）后，Python 层迭代从「列数 × 行数」降到「行数」：

    =============  =======  =======  ======
    序列            改前      改后     加速
    =============  =======  =======  ======
    white_line      3.64s    0.08s    45×
    kdj_k           8.82s    0.28s    31×
    kdj_j           7.98s    0.28s    28×
    =============  =======  =======  ======

## 为什么差在末位

递推是 `Y = α·X + (1 − α)·Y_prev`。pandas `ewm` 在 C 层按自己的顺序累积乘加，而按行版是 numpy 的向量乘加；两者在 float64 下**不是同一条求值路径**，故最后 1~2 位会不同。这不是「近似算法」——同一个数学序列，差在舍入。

## 决策：接受差，但**不接受判据翻转**

**接受**这条取舍的判据是：这些量**只被用来比大小**，不被用来逐位比对、也不参与对舍入敏感的累积（例如求导、差分放大）。B1 的用法正是比大小：`trend` 是「白线 > 黄线」、`low_j` 是「J < 8」。

**但接受它需要证据，而不是一句「浮点误差可忽略」**。故每次这类改动都要给出**判据的翻转数**：

    gate trend（白线 > 黄线）  通过 319,287 → 319,287   翻转 0（0.0000%）
    gate low_j（J < 8）        通过 188,072 → 188,072   翻转 0（0.0000%）

**零翻转**才是「结论不变」的直接证据；数值层的 4.75e-16 只说明「没写错」。两者缺一不可：只有数值差而无翻转证明，不知道会不会在别的数据上翻；只有翻转统计而无数值对照，不知道差异是不是更大。

## 什么时候**不**接受

同一条理由反过来用：若某个量**要参与逐位比对**（如「两个信号在同一天相等」这类判据），或它的差会被放大（求导、比值、再取对数），则向量化后必须先证明差不会跨过判据，或者干脆保留逐列实现。项目里 `sizer` 的股数取整、`limit_price` 的十进制半进位就属于**不能**接受末位差的那一类——前者会改变整手数，后者的差恰好落在「是否触限」那一分钱上（ADR-0002 已记）。

## Considered Options

- **保留逐列 `apply`**：逐位不变，但白线 45× 的代价在每次选股上付一遍（分钟量级）。**否决**：递推类指标只用于比大小，逐位一致的收益为零。
- **整列调一次 `ewm(adjust=False)`**（比按行还快）：它遇到缺失**沿用前值**——`[1, 2, NaN, 4, 5]` 在 `span=2` 下给出 `[1, 1.667, 1.667, 3.667, 4.556]`，第 3 位不是缺失而是上一根的值，等于把停牌日伪造成一个**有**指标值的交易日（ADR-0005）。**否决**：那不是浮点差，是语义差。
- **逐列但用 numba/cython**：能同时拿到逐位一致与速度，但要引入编译依赖与新工具链。**本轮不取**：按行版已经把这一处降到秒级以下，收益不再与代价匹配。

## Consequences

- **读代码的人会看到数值不逐位相同**。故 `_smooth_frame` 的 docstring 与对应提交信息都写明这一点，并附上翻转统计——否则下一个人会以为是 bug。
- **逐格对拍仍是必须的**：它证明「没写错」，翻转统计证明「结论不变」。两者的分工写在 `.scratch/smooth_dump_or_compare.py` 里。
- **`atr` 的 `_wilder_smooth` 仍是逐列**（播种规则不同：前 n 根的均值）。它目前只占全流程约 0.3%，故留着；若哪天它变贵，照本 ADR 的流程办（先对拍、再翻转统计）。
