# 信号层与策略层分离，不造统一策略抽象

本项目同时需要**时序回测**与**截面选股**。我们决定让二者共享一个**信号/因子层**（指标、过滤信号、排序因子），但**不**追求「一份策略定义同时驱动回测与选股」。

## Considered Options

- **完全分离**：回测走 Backtrader 事件驱动，选股走 pandas 截面计算，两套代码互不相干。代价是同一条件写两遍，必然漂移。
- **统一策略抽象**（被否决）：一份策略定义既跑时序回测、又做截面选股。
- **共享信号层**（采纳）：数据层与信号层公共，回测与选股各自组装。

## 决策

采纳共享信号层。选股规则既是独立产出，也可作为回测的入场过滤器；后者是前者的消费者，不是另一套架构。

## Consequences

否决统一抽象，是因为时序与截面在语义上不同：前者问「这只标的现在状态如何」，后者问「今天所有标的中谁最靠前」。强行统一会逼出一个又大又薄的抽象层，是本类项目最常见的失败模式。因此信号函数一律按**标的宽表（日期 × 标的）**计算，回测按列取时序、选股按行取截面——同一函数，两个消费方向。
